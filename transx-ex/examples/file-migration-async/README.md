# Async File Migration Example with transx-ex

This example demonstrates how to use `MigrateStorageAsync` to transfer files between two remote SSH servers, with real-time progress monitoring and cancellation support.

## Overview

`MigrateStorageAsync` returns a `*StorageHandle` immediately. The caller polls `handle.Progress()` to observe the transfer state and calls `handle.Wait()` to block until completion. Sending SIGINT cancels the running transfer via `handle.Cancel()`.

### Transfer Flow (strategy: relay)

```
[source SSH]  →  rsync pull  →  [local staging]  →  rsync push  →  [destination SSH]
```

## Async Behavior

### StorageHandle Lifecycle

`MigrateStorageAsync` launches the transfer in a background goroutine and returns a `*StorageHandle` immediately — the caller is never blocked waiting for I/O.

```
MigrateStorageAsync(dmm)
        │
        └─► goroutine: Plan → Execute pipeline
                │
                ├─ pending  (created, not yet running)
                ├─ running  (pipeline executing)
                └─ done | failed | cancelled
```

### Status Transitions

| Status | Meaning |
|--------|---------|
| `pending` | Handle created; goroutine not yet started |
| `running` | Transfer pipeline is executing |
| `done` | All steps completed successfully |
| `failed` | A step returned an error; `ErrMessage` is set |
| `cancelled` | `Cancel()` was called; transfer stopped early |

### Key APIs

| API | Description |
|-----|-------------|
| `handle.Progress()` | Returns a point-in-time snapshot: `Status`, `StartedAt`, `ElapsedSec`, `BytesTransferred`, `FilesTransferred`, `CurrentFile`, `ErrMessage`. Safe for concurrent use. |
| `handle.Status()` | Returns just the current status, without copying the whole snapshot. |
| `handle.Wait()` | Blocks until the goroutine exits. Returns the final error. |
| `handle.Cancel()` | Requests cancellation by closing the context. The running executor stops at the next I/O boundary. |

### Pattern Used in This Example

```go
handle := transxex.MigrateStorageAsync(dmm)

// SIGINT → cancel
go func() { <-sig; handle.Cancel() }()

// Poll at 200ms intervals while running
go func() {
    for { p := handle.Progress(); print(p.Status, p.ElapsedSec); sleep(200ms) }
}()

// Block until done
handle.Wait()

// Read final status
p := handle.Progress()
// done | failed | cancelled
```

## Prerequisites

- Go 1.26 or higher
- Docker installed and running
- rsync installed on the local machine

## Quick Start

### 1. Setup Environment

```bash
chmod +x setup_environment.sh migrate.sh

# Start source and destination SSH containers with test data
./setup_environment.sh all
```

This will:
- Build an SSH+rsync container image (Ubuntu 22.04 + openssh-server + rsync)
- Generate an SSH keypair in `./ssh_keys/`
- Start `transx-migrate-src` (port 3222) with test data in `/data/src`
- Start `transx-migrate-dst` (port 3223) with empty `/data/dst`
- Generate `config-ssh2ssh.json`

### 2. Run Migration

```bash
# Run migration
./migrate.sh -c config-ssh2ssh.json

# With verbose progress output
./migrate.sh -c config-ssh2ssh.json -v
```

### 3. Verify Result

```bash
./setup_environment.sh verify
```

## Configuration Files

### Template vs Generated

| File | Purpose |
|------|---------|
| `template-config-ssh2ssh.json` | Template with placeholders for your own servers |
| `config-ssh2ssh.json` | Auto-generated by `setup_environment.sh` — points to containers |

The `config-*.json` files are created by `setup_environment.sh all` and ignored by git.

### SSH → SSH (`template-config-ssh2ssh.json`)

```json
{
  "source": {
    "storageType": "filesystem",
    "path": "/data/src",
    "filesystem": {
      "accessType": "ssh",
      "ssh": {
        "host": "YOUR_SRC_HOST",
        "port": 3222,
        "username": "YOUR_USERNAME",
        "privateKeyPath": "/home/YOUR_LOCAL_USERNAME/.ssh/id_rsa"
      }
    },
    "filter": {
      "exclude": ["tmp", "logs"]
    }
  },
  "destination": {
    "storageType": "filesystem",
    "path": "/data/dst",
    "filesystem": {
      "accessType": "ssh",
      "ssh": {
        "host": "YOUR_DST_HOST",
        "port": 3223,
        "username": "YOUR_USERNAME",
        "privateKeyPath": "/home/YOUR_LOCAL_USERNAME/.ssh/id_rsa"
      }
    }
  },
  "strategy": "relay"
}
```

### Transfer Strategies

| Strategy | Description |
|----------|-------------|
| `relay` | Pull to local staging → push to destination. Reliable; requires rsync on local machine. |
| `auto` | Agent-forward for SSH→SSH: runs rsync on source, streams directly to destination. Requires SSH agent with key loaded. |

### Filter Options

| Field | Type | Description |
|-------|------|-------------|
| `exclude` | []string | Folder name patterns to exclude from transfer. Matched against folder base name at any depth. |
| `maxDepth` | int | Maximum scan depth; `0` = unlimited. |

## Troubleshooting

### SSH connection refused

```bash
./setup_environment.sh test-ssh

# Manual test
ssh -i ./ssh_keys/id_rsa -o StrictHostKeyChecking=no -p 3222 root@localhost
ssh -i ./ssh_keys/id_rsa -o StrictHostKeyChecking=no -p 3223 root@localhost
```

### rsync not found on local machine

The relay strategy requires rsync on the local machine running the Go program:

```bash
sudo apt-get install rsync   # Ubuntu/Debian
brew install rsync           # macOS
```

### Migration failed: staging directory

The relay strategy uses `/tmp/transxex-staging` as local staging. Ensure the path is writable:

```bash
ls -la /tmp/transxex-staging
```

### Permission denied on SSH key

```bash
chmod 600 ./ssh_keys/id_rsa
```

## Cleanup

```bash
./setup_environment.sh cleanup
```

This will:
- Stop and remove `transx-migrate-src` and `transx-migrate-dst` containers
- Remove generated SSH keys (`./ssh_keys/`)
- Remove generated config file (`config-ssh2ssh.json`)
