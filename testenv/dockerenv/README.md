# cm-centipede Docker-Based Migration Test Environment

A **source / target** Docker environment for exercising the migration features.
It is built on Ubuntu 22.04 + systemd, so `systemctl` works normally inside every container.

The layout is **role-split**: filesystem, object storage, and database each live in their own
container, which lets all **12 containers run at once without port conflicts**. Start and stop
with `dockerenv-up.sh` / `dockerenv-down.sh`, thin wrappers around `docker compose`.

| Role | Containers | Contents |
|------|------------|----------|
| filesystem | source / target | SSH + `/testdata` |
| object storage | source / target | SSH + MinIO |
| database | mariadb, mysql, postgresql, mongodb — each source / target | SSH + DB |

Four DBMSs are supported — **MariaDB, MySQL, PostgreSQL, MongoDB** — and the DB version is
selected in the `versions.env` file.

## Quick Start

```bash
cd dockerenv

# Start all 12 containers (build -> wait for healthy -> inject SSH keys -> print connection info)
./dockerenv-up.sh

# Rebuild without the cache
./dockerenv-up.sh --no-cache

# Skip the build (start from existing images)
./dockerenv-up.sh --no-build

# Stop everything
./dockerenv-down.sh
./dockerenv-down.sh --rmi        # also remove the images that were built
```

`dockerenv-up.sh` runs `docker compose up -d --wait` and waits until all 12 containers are
**healthy (role initialization finished)**, then injects the SSH keys into each container and
prints the connection info.

### Working with individual services

You can also drive `docker compose` directly. Pass `--env-file versions.env` on any command that
builds or creates containers — compose only auto-loads a file named `.env`, and every
`${*_VERSION}` in `docker-compose.yml` has a default, so omitting it silently builds the default
DB versions instead of failing.

```bash
# Start only specific services
docker compose --env-file versions.env up -d --wait mariadb-source mariadb-target

# Status / logs (no build args involved, so --env-file is optional)
docker compose ps
docker compose logs -f minio-source
```

## Supported DB Versions

DB versions are set in `versions.env`. When unset, the **default version** (marked ⭐) is built.

| Item | MongoDB | MariaDB | MySQL | PostgreSQL |
|------|---------|---------|-------|------------|
| **Default** | 7.0 ⭐ | 10.6 ⭐ | 8.0 ⭐ | 14 ⭐ |
| **Supported** | 6.0 · 7.0 ⭐ · 8.0 | 10.6 ⭐ · 10.11 · 11.4 · 11.8 | 8.0 ⭐ · 8.4 | 13 · 14 ⭐ · 15 · 16 · 17 |
| **Repository** | MongoDB official apt repo | MariaDB official repo (`mariadb_repo_setup`) | Oracle official apt repo (`mysql-apt-config`) | PostgreSQL PGDG apt repo |
| **`versions.env` variable** | `MONGODB_VERSION` | `MARIADB_VERSION` | `MYSQL_VERSION` | `POSTGRESQL_VERSION` |

```bash
# versions.env example
MARIADB_VERSION=10.11
MONGODB_VERSION=8.0
POSTGRESQL_VERSION=16
```

> The supported versions are the ones the official Ubuntu 22.04 (jammy) repositories ship. Choosing a version outside this list makes the build fail at `apt-get install`.

> `dbmsFilter.databases[].targetMapping.dstName` — and not by the connection: `dstConnection`

> authentication at the target database instead.

## Source Data Reference (MariaDB as the baseline)

> MariaDB uses `shop_db_mariadb.sql` / `hr_db_mariadb.sql`, MySQL uses `shop_db_mysql.sql` / `hr_db_mysql.sql`,
> PostgreSQL uses `shop_db_pg.sql` / `hr_db_pg.sql` (a PL/pgSQL port),
> and MongoDB uses `shop_db_mongo.js` / `hr_db_mongo.js` (mongosh initialization scripts).
> On a source DB container the build selects `01-setup-<db>.sh` as `init.sh`, which configures the
> accounts and loads the schema and data.

### UTF-8 Encoding Verification Data

All regular sample data in this environment is ASCII. To catch a migration that silently loses a
charset, collation or file encoding, each source carries a small, clearly labeled block of
**deliberately multibyte** data (Korean, Japanese, emoji). After a migration, compare these rows
and files byte for byte on the target — mojibake here means the encoding was not preserved.

| Source | Where | Contents |
|--------|-------|----------|
| `shop_db` | `categories` (2 rows), `customers` (2 rows) | Korean / Japanese names and descriptions, an emoji address |
| `hr_db` | `departments` (2 rows), `leave_types` (2 rows) | Korean / Japanese department and leave-type names |
| MinIO | `raw-data/utf8_encoding_check.json` | Korean, Japanese and emoji values in JSONL |
| Filesystem | `documents/한글_인코딩_검증.txt`, `documents/日本語_エンコード検証.txt`, `data/json/metadata/utf8_encoding_check.json` | Multibyte **filenames** as well as multibyte content |

These rows push the totals above to 12 categories / 10 customers in `shop_db` and
8 departments / 7 leave types in `hr_db`.

## Initialization Flow

Every container starts only its own role service plus the shared `testenv-init.service`.
`testenv-init.service` runs `/opt/testenv/init.sh`, the role script copied in at build time; once
that service reaches `active`, the compose healthcheck reports healthy (which is what
`dockerenv-up.sh --wait` waits for).

```
systemd boot
  ├── ssh.service          → start the SSH server (port 22)
  ├── <role service>       → minio.service / mariadb.service / mysql.service / postgresql.service / mongod.service
  └── testenv-init.service → /opt/testenv/init.sh (one of the scripts below is copied in per role)
        source:  03-setup-filesystem.sh | 02-setup-minio.sh | 01-setup-<db>.sh
        target:  target-fs.sh | target-minio.sh | target-db-<db>.sh
```

- **filesystem** — source: build the full `/testdata` dataset / target: empty `/testdata`
- **minio** — source: 6 buckets + uploaded objects / target: 6 empty buckets
- **database** — source: accounts + load shop_db and hr_db / target: accounts + empty shop_empty_db and hr_empty_db

## Stack

| Item | Details |
|------|---------|
| Base OS | Ubuntu 22.04 LTS |
| Init system | systemd (`--privileged` + `cgroup: host`) |
| Orchestration | Docker Compose (12 services, healthcheck-driven `--wait`) |
| DBMS | MariaDB · MySQL · PostgreSQL · MongoDB (versions set in `versions.env`) |
| Object storage | MinIO (latest stable binary) |
| Client tooling | mc (MinIO Client) |

> **Note**: the containers require the `--privileged` flag and a `/sys/fs/cgroup` mount. Use this for local development and testing only, never in production.
